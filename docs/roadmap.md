## In progress

- **The Sample Data Installer block in Rock**, built in the Rock repository against the loader package. It shows Core 1, Core 3, and Full 7 as cards built from the package index, so each release updates them, and downloads the chosen package from a hosted `index.json`, beside the old sample data block. It landed on Rock's develop branch on 2026-10-27, on loader 0.1.0-alpha.13. What is left: one Rock change that bumps it to the newest loader, which gives Rock the signed index check, and adds the login password field, and a page for it in Rock.
- **The release workflow** (decisions 127 to 130; see [Publishing a release](maintaining.md#publishing-a-release)). `.github/workflows/release.yml` builds each Rock release in `release/rock-releases.json`, writes and verifies every package, and runs the publishing gate. On a version tag it pushes the loader to nuget.org and uploads the packages, receipts, and index to Azure, the index last. A dry run on GitHub's `windows-2025` runner on 2026-10-22 built Rock 21.0.2, ran SQL Server 2025, passed verify on all three packages, and passed the gate. Its Packages job took 66 minutes (about 30 to build Rock, 6 for SQL Server, and 28 for verify). A self-hosted runner stays a fallback. The one-time setup in [Maintaining](maintaining.md#one-time-setup) is done (2026-10-22): the Azure identity and its role, nuget.org trusted publishing for `SparkDevNetwork.Rock.SampleData.Loader`, and the `release` environment with its approvers and variables. What is left:
  - A stable release (for example `v1.0.0`), which updates `index.json` for every Rock. The first prerelease, `v0.1.0-alpha.10` on 2026-10-23, published the loader to nuget.org and all three packages with `index-prerelease.json`.
  - Change the Rock 21.0.2 entry from a develop commit to its tag once Rock tags it, and the Rock 20.0.10 entry (release-20.0, added for `v0.1.0-alpha.13`) to the newest Rock 20 tag.
  - Rock 20 and Rock 21 packages from `v0.1.0-alpha.13` on. Each package serves every dot release of its major (decision 52). On 2026-10-23, Core 1, Core 3, and Full 7 passed every verify check on Rock 20.0.10 unchanged, and its trusted base had the same schema hash as Rock 21.0.2's.
  - **The first signed index** (decision 172). The index signature is built: the Publish job signs the index with `sampledata-index-1` in Azure Key Vault before it publishes anything, and loaders from 0.1.0-alpha.14 read only a signed index (see [The signature](../loader/README.md#the-signature) and [Signing keys](maintaining.md#signing-keys)). The vault, both keys, the signer role, and the variables were set up on 2026-10-27. `v0.1.0-alpha.14` published the first signed index on 2026-10-28 (see [Releases so far](maintaining.md#releases-so-far)). What is left: bump Rock's installer block to that loader and add its login password field, in one Rock change. Raised by the Sentinel security review of the installer block (SparkStealth/Rock-Mirror#65). It is required before Cast logins, and before v1.0.0 fixes the index format. alpha.14's packages also raise the minimum loader to 0.1.0-alpha.14 (decision 158), because an older loader lacks the Calendar part, Alisha's `replacesAdmin` field, and the connection due-date fields.
